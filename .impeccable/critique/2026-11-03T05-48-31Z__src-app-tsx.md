## Specificity and impression

The workflow is recognizably a transcription app, but the dark card-based dashboard could belong to many products and feels less like purpose-built Mac software. The strongest opportunity is to organize attention around import, process, review and save. The source detector reported zero findings; this does not establish accessibility or visual quality.

## Strengths

- The prominent drop area names supported formats and offers Cmd-O.
- Discard warnings protect unsaved work and explain that original audio remains untouched.
- Model compatibility guidance, queue status and progress provide useful safeguards.

## Priority issues

1. **P1 — Keyboard access to core actions.** The drop zone and queue selection use click-only containers, and transcript tabs do not expose selected state. Keyboard and assistive technology users can struggle to import or review. Use semantic controls and tab semantics; verify keyboard and VoiceOver operation. Suggested: $impeccable harden. See `src/components/FileDropZone.tsx:162`, `src/components/QueuePanel.tsx:123`, `src/components/TranscriptionPanel.tsx:147`.
2. **P1 — Completion loses momentum.** The displayed result clears until a queue item is selected, adding an unexplained step after processing. Auto-select a completed item when appropriate and make review and saving clear. Suggested: $impeccable onboard. See `src/App.tsx:337`.
3. **P2 — First-run decisions compete.** Model and system information, output tabs, and export formats appear before a file exists. Prioritize importing and reveal output and export controls when relevant; explain the recommended model in plain language. Suggested: $impeccable distill. See `src/App.tsx:377` and `src/components/ExportPanel.tsx:148`.
4. **P2 — Errors do not consistently guide recovery.** The global error displays the raw message with no contextual next step. Give plain-language context, a recovery action where possible, and appropriate alert semantics. Suggested: $impeccable clarify. See `src/App.tsx:590`.
5. **P2 — Starting prerequisites are unclear.** A disabled Start Queue and model choice do not clearly explain the next step; instructions also say Start while the button says Start Queue. Explain why a model is needed and when a download is required, and align labels. Suggested: $impeccable onboard. See `src/App.tsx:412` and `src/components/TranscriptionPanel.tsx:229`.

## Cognitive load and emotional journey

The first view divides attention across import, model selection, library and export; model/language lists and five export options can exceed four choices. The drop target is approachable, but model and disabled-start uncertainty create a valley before processing. Progress builds confidence; having to select a completed item interrupts the payoff. Unsaved-work warnings provide reassurance.

## Persona red flags

- **First-timer:** sees model, JSON and ASS before understanding what is needed, and a disabled start action without an adjacent explanation.
- **Keyboard and screen-reader user:** cannot reliably operate the click-only drop zone and queue selection, while tabs lack announced selection state.
- **Power user:** benefits from shortcuts and batch actions but must reselect output and navigate dense row controls.

## Minor observations

Small muted labels may be difficult to read; contrast was not measured. Start Queue sounds batch-oriented even for one file. The window uses a web-dashboard composition beneath a native title bar.

## Questions to consider

What should appear immediately after a single recording finishes? Can a recommended local model reduce the first decision? Could library and export controls appear when there is something meaningful to save?
